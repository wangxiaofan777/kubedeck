## Context

创建接口是「每类资源一个集合路径」，服务端会校验请求体 `apiVersion`/`kind` 与路径一致（`resource-browser` 的「对象身份不一致」场景）。弹窗由资源列表页打开，模板固定为当前类型，但编辑器允许改整段 YAML，于是存在「YAML 写了别的类型 → 提交到旧路径 → 422」的错配。资源发现已经通过 `GET /api-resources` 暴露 `group`/`version`/`resource`/`kind`/`namespaced`/`verbs`，前端具备解析目标所需的全部信息。

## Goals

- 弹窗内写哪种类型，就创建哪种类型，不再受打开弹窗时的页面类型限制。
- 提交前能发现「集群里没有这个 kind」「该类型不允许创建」「命名空间字段不合法」，不发无意义请求。
- 权限仍完全由服务端判定，前端解析只用于选择路径与提示。

## Non-Goals

- 不做通用的「资源类型选择器」；创建入口仍在各资源页，YAML 是唯一事实来源。
- 不新增后端接口，不改创建 API 的契约。
- 不为未内置的 CRD 生成列表/详情页；创建成功后停留在当前页并提示结果。

## Decisions

### 1. 目标解析放在提交时，提示使用防抖解析

提交时解析 YAML 得到：

```ts
{ apiVersion: "apps/v1", kind: "Deployment", name: "web", namespace: "default" }
```

按 `apiVersion` 拆出 group/version（`v1` → group 为空），在资源发现结果中查找：

1. 精确匹配 `group + version + kind`；
2. 精确失败时按 `group + kind` 匹配，优先带 `create` 动词的版本（兼容发现返回多个版本）；
3. 仍找不到 → 本地错误，不发请求。

提示区域（「将创建 X，并跳转到 X 页面」）用 300ms 防抖后的解析结果驱动，避免每次按键都重新解析大段 YAML；解析失败时保留既有 YAML 错误提示。

### 2. 路径与命名空间以解析结果为准

- 命名空间级资源：`metadata.namespace` 优先，缺省用弹窗当前的命名空间；查询参数与请求体使用同一个值，满足服务端「namespace 与查询参数一致」校验。
- 集群级资源：若 YAML 写了非空 `metadata.namespace`，本地直接提示「集群级资源不能设置 namespace」，不提交。
- 目标发现结果不含 `create` 动词：本地提示「该资源类型不支持创建」，与服务端 `UNSUPPORTED` 语义一致。
- dryRun 与正式创建走同一套解析，保证「校验通过」与「实际创建」目标一致。

### 3. 创建成功后的导航

- 目标 GVR 能反查到控制台内置资源类型（`RESOURCE_TYPES` 中 `gvr` 完全一致）：跳转到该类型的详情页 `/clusters/{c}/{targetKey}/{ns}/{name}`，并失效资源列表查询。
- 无法反查（未内置的 CRD）：关闭弹窗、停留当前页，提示「已创建 {kind}/{name}」，不猜测路由。
- 目标与当前页类型一致时行为与现状完全相同。

### 4. 权限边界

弹窗的「新建」按钮仍按当前页面类型做 `create` 权限预检；跨类型创建时不在前端伪造授权，直接由 apiserver 判定，403 通过既有错误提示展示。发现结果中的 `verbs` 只用于「该类型是否支持创建」的能力判断，不当作授权结果。

### 5. 资源发现的加载与缓存

新增 `useApiResources(cluster)`（react-query，`staleTime` 5 分钟），弹窗打开时复用缓存；发现失败时按「无法解析目标」处理并提示重试，不阻塞当前类型的创建（当前类型直接用页面已知的 GVR）。

## 关键时序

```
用户改 YAML ──(300ms 防抖)──> 解析身份 ──> 发现匹配 ──> 弹窗提示目标类型
提交（创建/校验）
  ├─ 解析失败 → 本地错误，不请求
  ├─ 未发现目标 / 无 create 动词 / namespace 非法 → 本地错误，不请求
  └─ 解析成功 → POST /clusters/{c}/{目标 resource}?namespace=...
        ├─ 201 → 失效列表 → 有内置页面则跳详情，否则提示并停留
        └─ 4xx/5xx → 既有错误提示（409 同名、403 无权限、422 身份不一致）
```

## 性能与兼容

- 发现结果按集群缓存 5 分钟，弹窗打开与提交不额外增加高频请求；防抖解析只在编辑时计算一次。
- 不改变后端与 OpenAPI；旧客户端行为不受影响。
- 大 YAML（接近 1 MB）解析仍在浏览器主线程，沿用现有编辑器输入规模；防抖避免每次按键重复解析。

## 测试策略

- 类型检查与 lint：`npm run typecheck`、`npm run lint`。
- 浏览器端到端（dev 环境）：
  1. Deployments 页打开弹窗，把 YAML 改为 ConfigMap → 出现跨类型提示 → 创建成功 → 跳转 `/configmaps/default/{name}`，集群中存在该 ConfigMap；
  2. 改为不存在的 `kind: Widget` → 本地错误，且审计无新记录；
  3. 集群级资源（如 Namespace）带 namespace → 本地错误；
  4. 同类型创建（Deployment）保持原有行为；
  5. 无权限账号跨类型创建 → 服务端 403，页面展示错误。
- 清理测试对象，确认审计只记录实际发出的 create。
