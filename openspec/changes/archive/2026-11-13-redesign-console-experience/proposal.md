# 提案：重设计控制台信息架构与交互

## 背景

当前控制台只有 4 个路由，创建、编辑、扩缩容、回滚、删除、搜索全部以 Modal 承载，全仓没有 Drawer、没有面包屑、没有页面标题；命名空间是侧栏里的一个隐藏模式；总览页不可下钻；详情页的 Owner 引用不可点击。用户反馈「交互不友好、很多事都在一个页面完成、显得 low」。这不是样式问题，是缺少页面层级与任务空间。

## 目标

1. 建立「集群 → 命名空间 → 资源类型 → 对象」四层可感知的导航，面包屑与页面标题常驻。
2. 把高频任务从 Modal 迁移到独立页面或右侧 Drawer：创建/编辑、批量删除、扩缩容、回滚、日志。
3. 命名空间成为页面级上下文（URL + 面包屑 + 显式切换），不再是全局隐藏状态。
4. 全局搜索升级为命令面板（`Ctrl/⌘ + K`），同时支持跳转与动作。
5. 总览成为可下钻的仪表盘；详情页成为工作台（主区 + 右侧上下文栏 + 关联资源跳转）。
6. 建立最小设计系统：品牌色、字号、间距、卡片、表格密度、状态语义、空/错/加载态。
7. 修复首屏 4.7 MB 主包：Monaco 完全按需加载。

## 非目标

- 不改变后端 API 契约（除新增页面所需的管理接口复用）。
- 不引入第三方图表库；趋势与分布用内联 SVG 实现。
- 不追求移动端适配；桌面优先，最小宽度 1280。
- 不做国际化框架；统一中文文案与日期格式。

## 影响

- `web/src/app`：外壳、主题、导航、命令面板。
- `web/src/features/*`：列表、详情、总览、审计、日志全部重排。
- `web/src/lib`：新增路由/标题/面包屑工具、格式化工具。
- 不涉及数据库迁移。
