# 提案：补齐集群接入与管理界面

## 背景

后端已具备集群登记、凭据轮换、删除、健康探测与角色绑定接口，但前端没有任何集群管理入口。全新部署后，非管理员看到「请联系平台管理员接入集群」，而平台管理员也没有入口，只能用 curl 调 API。产品在第一步就是死路。

## 目标

1. 平台管理员可在界面完成：接入集群（kubeconfig 或 server + token）、查看健康与版本、轮换凭据、修改展示名与标签、删除集群。
2. 接入采用三步向导：填写凭据 → 服务端校验（连通性、版本、权限）→ 确认创建；失败时给出可执行的修复建议。
3. 集群设置页提供健康状态、凭据元数据（不含明文）、访问绑定管理与危险操作区。
4. 非管理员不显示管理入口；直接访问返回 403 状态页。
5. 无集群时首页进入接入引导，而不是一句"请联系管理员"。

## 非目标

- 不做从零安装 Kubernetes（集群生命周期不在项目范围）。
- 不在前端保存或回显凭据明文。
- 不实现用户创建/删除；用户来自 OIDC 首次登录。

## 影响

- 新增页面：`/clusters`、`/clusters/new`、`/clusters/:cluster/settings`。
- 新增前端 API：集群 CRUD、凭据元数据与轮换、用户搜索、角色、绑定。
- 复用现有后端接口；仅在必要时补充「接入预检」只读端点（不落库）。
