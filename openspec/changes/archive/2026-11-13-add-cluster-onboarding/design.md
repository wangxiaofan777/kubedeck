# 设计：集群接入与管理界面

## 1. 页面与路由

| 路由 | 内容 | 权限 |
|---|---|---|
| `/clusters` | 集群卡片/表格：名称、版本、健康、最近探测、操作 | 平台管理员 |
| `/clusters/new` | 三步接入向导 | 平台管理员 |
| `/clusters/:cluster/settings` | 设置：概览、凭据、访问控制、危险操作 | 平台管理员 |

非管理员访问管理路由时渲染 `Result 403`，侧栏不显示入口。`/clusters` 在只有只读权限时仍可展示健康信息？——为避免泄露，本期仅管理员可见。

## 2. 接入向导

步骤 1「连接信息」：

- 模式切换：`kubeconfig` 粘贴 / `server + token`。
- 集群标识：名称（DNS label，创建后不可改）、展示名、标签。
- 实时本地校验：kubeconfig 可解析、server 为 https、名称合法。
- 安全提示：凭据只用于服务端加密存储；不接受文件路径凭据。

步骤 2「校验」：

- 提交 `POST /api/v1/clusters` 前先做一次只读预检（新增 `POST /api/v1/clusters/probe`，不落库、不返回凭据）：
  - TLS/认证是否通过；
  - 版本是否在 1.34–1.37；
  - 平台 SA 是否具备 impersonate 权限（以用户身份执行一次 SSAR 代理）。
- 展示探测结果：版本、server、耗时、警告（如 `InsecureSkipTLSVerify`）。
- 失败分类：地址不可达 / 证书失败 / 凭据无效 / 版本不支持 / 权限不足；每类给出修复建议。

步骤 3「确认」：

- 摘要 + 「创建集群」；成功后跳转设置页并展示首次健康检查状态。
- 创建失败（409/400）留在当前步骤并保留输入。

## 3. 集群设置

Tab：

1. **概览**：健康状态、版本、server、最近探测消息、探测时间线（最近 10 次，需后端暴露或前端轮询记录）。
2. **凭据**：authType、指纹、keyVersion、rotatedAt、expiresAt；「轮换凭据」打开 Drawer，提交后失败不覆盖旧凭据。
3. **访问控制**：按集群列出绑定；添加用户（搜索）、角色（viewer/developer/cluster_admin）、命名空间（`*` 或具体）。保存调用 `PUT /admin/role-bindings`。
4. **危险操作**：修改展示名/标签；删除集群（输入集群名确认）。

## 4. 后端补充

`POST /api/v1/clusters/probe`：

- 请求体与创建相同（不含 name），仅平台管理员。
- 调用 `kube.ParseCredential` + 一次性 `DirectCluster` 探测（5 秒），返回 `{server, version, latencyMs, warnings[]}`。
- 不写数据库、不记录凭据；请求体审计只存哈希。

## 5. 状态与错误

- 空列表：引导卡片「接入第一个集群」。
- 健康异常：卡片顶部红色状态条 + 消息 + 「轮换凭据」快捷入口。
- 凭据轮换：Drawer 内保留旧凭据元数据对比，确认后提交。
- 所有危险操作在 Drawer 内展示影响说明，删除需输入集群名。

## 6. 审计

- 创建/轮换/删除/绑定变更沿用现有审计中间件。
- 新增 probe 不入操作审计（只读预检），但记录服务端日志。
